# Laress

Вёрстка сайта Laress по макету из Figma. После вёрстки её переносят на WordPress (кастомная тема).

## Стек

- **Сборщик:** Vite
- **Код:** нативные HTML + CSS + JS, без фреймворков (React, Vue, Tailwind, jQuery и т. п. не используем)
- **Источник дизайна:** Figma — через MCP `figma-api` (Framelink) и локальный кэш `.figma/`
- **Цель:** кастомная тема WordPress (этап 2)

## Этапы работы

1. **Десктоп.** Сначала верстаем только десктопную версию по макету.
2. **Проверка.** Пользователь проверяет десктоп. Без его подтверждения дальше не идём.
3. **Адаптив.** Адаптивные версии (планшет, мобильные) делаем только по прямой команде пользователя. До этой команды медиазапросы под меньшие экраны не пишем.
4. **WordPress.** Готовую вёрстку переносим в тему WordPress.

Работаем по секциям или по страницам. Каждый блок перед сдачей сверяем с макетом (см. «Сверка с макетом»). Закончив блок, коротко сообщаем, что сделано, итог сверки и что нужно проверить.

## Работа с Figma

Доступ к файлу — только через MCP `figma-api` (Framelink, Figma REST API). Официальный коннектор claude.ai figma под другим аккаунтом и к файлу доступа не имеет — его не используем. Инструментов `get_design_context`, `get_screenshot`, `get_variable_defs` у Framelink нет.

- **fileKey:** `xDnfQshLiYi4kvHbeJfZav`. Страницы — секция «Дизайн / Основные страницы» (`966:41552`), UI Kit — `827:12045`.
- **Сначала кэш, потом API.** Лимит Figma API ограничен, поэтому:
  - данные всех страниц уже выгружены: `.figma/pages_966-41552.yaml` (UI Kit — `.figma/ui-kit_827-12045.yaml`);
  - эталоны всех фреймов (PNG 1x) — в `.figma/screenshots/`, список с nodeId — в `.figma/README.md`;
  - картинки уже скачаны: исходники в `assets-src/images/<страница>/`, иконки в `src/assets/icons/`.
  К API (`get_figma_data`, `download_figma_images`) идём только за тем, чего нет в кэше, или если дизайнер менял макет. Каждую новую выгрузку сохраняем в `.figma/` и дописываем в `.figma/README.md` с датой.
- **Порядок для каждого блока:**
  1. `npm run figma:tree -- <nodeId>` — дерево узла из кэша с раскрытыми стилями: раскладка (row/column, padding, gap, размеры), цвета, шрифты, тексты. Это главный источник размеров и отступов.
  2. Эталон — PNG фрейма из `.figma/screenshots/` (или вырезка из него).
  3. Токены — уже в `src/styles/base/variables.css`; новые цвета/размеры добавляем туда же.
- **Ловушки макета:**
  - в текстах `[nbsp]` — неразрывный пробел (`&nbsp;`), `[br]` — принудительный перенос (`<br />`), переносим дословно;
  - обводки (strokes) в Figma не меняют размер блока: тонкие линии делаем `box-shadow: inset`, а у кнопок с рамкой вычитаем 1px из паддингов;
  - если в одном фрейме есть фото с наложенным текстом — скачиваем исходник по `imageRef` (без текста), иначе — экспорт слоя по nodeId (с нужным кадрированием);
  - фреймы одной страницы иногда противоречат друг другу (старая/новая версия шапки и т. п.) — берём более новый вариант и сообщаем пользователю.
- Размеры, отступы, цвета и шрифты берём из Figma точно, не на глаз. Абсолютное позиционирование — только там, где его нельзя заменить flex/grid; инлайн-стилей нет.
- Если ссылка или nodeId неизвестны, спрашиваем у пользователя, а не угадываем.

## Сверка с макетом

Каждую свёрстанную секцию обязательно сверяем с макетом до того, как отдать её на проверку пользователю.

- **Как сверяем:**
  1. Эталон — PNG фрейма из `.figma/screenshots/`.
  2. `npm run compare -- …` (одна секция) или `npm run compare:page -- <страница>` (все секции страницы по `.figma/sections.json` — новые страницы добавляем туда). Скрипт снимает страницу в Playwright при ширине эталона (1440), кладёт в `.compare/` картинки «бок о бок», наложение и карту отличий, печатает % отличий и лучший вертикальный сдвиг эталона.
  3. Норма: ≤ ~2% при сдвиге 0–2px — это сглаживание текста. Больше — смотрим `*-diff.png` / `*-side.png` и ищем причину; положения элементов проверяем по `getBoundingClientRect` против цифр из Figma.
  4. Масштаб: `npm run compare:page -- <страница> --scale` — то же на 1920 с эталоном, увеличенным в 1.333 раза.
- **Что проверяем:**
  - размеры и положение блоков, отступы между ними и внутри;
  - типографику: шрифт, размер, начертание, межстрочный интервал, межбуквенный интервал, цвет;
  - цвета, фоны, градиенты, тени, скругления, бордеры;
  - изображения и иконки: размер, обрезку, качество;
  - выравнивание по сетке и контейнеру;
  - тексты: совпадают с макетом дословно.
- **Допуск:** расхождение не больше 1–2 px. Всё, что больше, исправляем до сдачи.
- Расхождения, которые нельзя устранить (например, браузер иначе рендерит шрифт или в макете ошибка), перечисляем пользователю при сдаче секции.
- После правок сверяем снова. Секция считается готовой только после повторной сверки.
- Адаптивные версии сверяем так же, с соответствующими фреймами макета на их ширине.

## Изображения

- **Экспорт по фрейму.** Каждое изображение берём из Figma отдельно, по nodeId его фрейма или слоя (`download_figma_images` в `assets-src/images/<страница>/`, затем `npm run images`). Скриншоты целых секций как картинки не используем. Текст, кнопки и фоны-заливки верстаем кодом, а не картинками.
- **Плотность.** Растровые изображения экспортируем в 2x для retina.
- **Оптимизация при подключении, без потери качества:**
  - фото → WebP высокого качества (q≈85–90), исходник в JPG оставляем как fallback через `<picture>`;
  - графика с прозрачностью → WebP lossless или оптимизированный PNG;
  - иконки и векторы → SVG, прогнанный через SVGO (`viewBox` не удалять);
  - после оптимизации сверяем картинку с исходником, видимых артефактов быть не должно.
- Оптимизацию делаем при сборке через Vite (`vite-plugin-image-optimizer` на sharp + svgo) или скриптом на sharp. Настройки качества держим в конфиге.
- У каждого `<img>` есть `width`, `height` и осмысленный `alt`. Для изображений ниже первого экрана ставим `loading="lazy"`.
- Имена файлов: латиница, kebab-case, по смыслу (`hero-bg.jpg`, `icon-arrow.svg`), а не `Rectangle 12.png`.

│   │   └── main.js

│       ├── icons/

## Правила вёрстки

- **БЭМ** для классов (`block__element--modifier`). Каждая секция — отдельный блок; его потом проще превратить в template-part WordPress.
- Семантика: `header`, `main`, `section`, `nav`, `footer`, заголовки `h1`–`h6` по иерархии, на странице ровно один `h1`.
- Токены из Figma — в `:root` как CSS-переменные (`--color-*`, `--font-*`, `--space-*`). Захардкоженных цветов в компонентах нет.
- Контейнер с максимальной шириной по макету; ширина десктопного макета указана в Figma.
- Единицы: в исходном CSS пишем `px` ровно как в Figma (макет 1440). При сборке `postcss-pxtorem` переводит их в `rem` (1rem = 16px), значения 1px остаются в `px`.
- Масштабирование: корневой `font-size` растёт от 16px на 1440 до 21.33px на 1920 (`src/styles/base/typography.css`), поэтому вся вёрстка пропорционально увеличивается; шире 1920 — фиксируется и центрируется. Размеры, которые считаются в JS, умножаем на масштаб (`fontSize корня / 16`).
- Интерактив (hover, focus, active) делаем по макету. Если состояний в макете нет — аккуратный дефолт, видимый `:focus-visible` обязателен.
- JS — ES-модули, без зависимостей, если задачу можно решить нативно. Внешнюю библиотеку (например, слайдер) подключаем только после согласования с пользователем.
- Подключение шрифтов: локальные woff2 + `font-display: swap`.

## Подготовка к WordPress

Верстаем так, чтобы перенос был механическим:

- Повторяющиеся части (header, footer, карточки) — в `src/partials/`. Они станут `header.php`, `footer.php` и `template-parts/*`.
- Повторяющиеся элементы (карточки, пункты списков, слайды) верстаем одинаковой разметкой, чтобы потом обернуть их в цикл.
- Контент, который будет редактироваться в админке (тексты, изображения, ссылки), не зашиваем в CSS (например, `background-image` с контентной картинкой — через `<img>` или инлайн-переменную).
- Меню — обычный `<ul>` в `<nav>`, совместимый с `wp_nav_menu`.
- Формы верстаем с расчётом на Contact Form 7 или аналог (стандартные `input`/`label`, без кастомной JS-логики отправки).

## Команды

```bash
npm install        # установка зависимостей
npm run dev        # дев-сервер
npm run build      # сборка в dist/
npm run preview    # просмотр сборки
npm run images     # PNG-исходники assets-src/images → src/assets/images (.webp + .jpg/.png), настройки в images.config.js
npm run figma:tree -- <nodeId>      # дерево узла из кэша Figma со стилями и текстами
npm run compare -- --ref .figma/screenshots/<эталон>.png --name <секция> [--selector .hero] [--ref-y 0 --ref-h 850]
                   # сверка секции с макетом (нужен npm run dev), результат в .compare/
npm run compare:page -- <страница> [--scale]   # сверка всех секций страницы по .figma/sections.json
```

- Партиалы подключаются в HTML комментарием `<!-- @include src/partials/header.html -->` (плагин в vite.config.js).
- Кэш данных Figma и эталоны для сверки — в `.figma/` (индекс в `.figma/README.md`).
