# Парсер каталога для WordPress: план работ

## 1. Задача

Собрать открытые данные о товарах (название, описание, цена, изображения) с сайтов брендов, перевести на русский, пересчитать цены в рубли и загрузить всё в WooCommerce на VPS клиента. Сбор **разовый**. Разрешение брендов на использование контента есть.

Парсер делаем **плагином WordPress** с собственным разделом в админке. В админке добавляем ссылки на сайты, запускаем сбор, видим прогресс и результат.

### Источники (замер от 17.11.2026, по sitemap)

| Сайт | Платформа | Товаров | Способ сбора |
|---|---|---|---|
| mdmaison.com | своя | 17 250 | HTML-страница товара: JSON-LD / разметка |
| serax.com | Shopify | 2 804 | `/products/<handle>.js` |
| jlcoquet.com | Shopify | 2 693 | `/products/<handle>.js` |
| fr.lalique.com | Shopify | 1 020 | `/products/<handle>.js` |
| degrenne.com | Shopify | 935 | `/products/<handle>.js` |
| daum.fr | Shopify | 620 | `/products/<handle>.js` |
| **Итого** | | **≈ 25 300** | |

- Около 830 товаров J.L Coquet есть и на mdmaison, и на jlcoquet.com. Их нужно убрать как дубли (этап 6).
- Shopify отвечает `429 Too Many Requests`, если слать запросы часто. Поэтому всё делаем через очередь с паузами, а `products.json` массово не запрашиваем.

### Ожидаемый объём

- ~125 тыс. изображений, если на товар приходится ~5 фото. Это оценка, точное число будет после этапа 0. После сжатия займут ~40–60 ГБ.
- База данных WooCommerce: 2–4 ГБ.
- Тексты для перевода: название и описание товара плюс атрибуты. Точный объём в символах посчитаем на этапе 0.

## 2. Архитектура

```
Админка WP (раздел «Импорт каталога»)
   │  ссылки на сайты, настройки, кнопки запуска, прогресс, логи
   ▼
Очередь задач (Action Scheduler из WooCommerce + системный cron / WP-CLI)
   │
   ├─ 1. Discovery  — sitemap → список URL товаров
   ├─ 2. Fetch      — загрузка данных товара (лимит частоты, повторы)
   ├─ 3. Parse      — адаптер под площадку → единый формат
   ├─ 4. Dedupe     — поиск дублей между источниками
   ├─ 5. Translate  — перевод на русский (API, пакетами, с кэшем)
   ├─ 6. Price      — EUR → RUB по курсу из настроек
   ├─ 7. Images     — скачивание, WebP, загрузка в медиатеку
   └─ 8. Import     — создание товаров WooCommerce
   ▼
Промежуточные таблицы (staging): здесь хранятся сырые и обработанные данные
   ▼
WooCommerce: товары, вариации, категории, бренды
```

Ключевые решения:

1. **Staging перед WooCommerce.** Сначала всё собираем в свои таблицы и только потом импортируем. Тогда любой этап можно перезапустить (например, перевод или курс), не трогая сайты-источники повторно.
2. **Каждый этап идемпотентный.** У каждого товара есть статус. Если процесс упал, после перезапуска он продолжит с того же места.
3. **Адаптеры по площадкам.** `ShopifyAdapter` (один на все 5 Shopify-сайтов), `MdMaisonAdapter` и `GenericAdapter`, который берёт данные из schema.org/JSON-LD и подходит для новых сайтов. Площадка определяется по ссылке автоматически.
4. **Тяжёлую работу делает WP-CLI, а не браузер.** Админка только ставит задачи в очередь и показывает их статус. Сами задачи выполняет `wp laress-import run` под systemd или по cron, поэтому нет таймаутов PHP и Nginx.
5. **Сырые данные храним всегда.** Исходный JSON или HTML-фрагмент каждого товара сохраняется. Если ошибёмся в парсинге, переразберём без повторных запросов к сайту.

## 3. Плагин: структура

```
wp-content/plugins/laress-importer/
├── laress-importer.php          # bootstrap, хуки активации (создание таблиц)
├── includes/
│   ├── Admin/                   # страницы админки, AJAX/REST для прогресса
│   ├── Adapters/                # ShopifyAdapter, MdMaisonAdapter, GenericAdapter
│   ├── Pipeline/                # Discovery, Fetch, Parse, Dedupe, Translate, Price, Images, Import
│   ├── Http/                    # HTTP-клиент: rate limit, backoff на 429, User-Agent, прокси
│   ├── Translate/               # провайдер перевода + кэш + глоссарий
│   ├── CLI/                     # команды WP-CLI
│   └── Db/                      # схема и репозитории staging-таблиц
└── assets/                      # JS/CSS админки (нативные, без фреймворков)
```

### Таблицы staging

| Таблица | Что хранит |
|---|---|
| `li_sources` | источник: URL, площадка, статус, настройки (задержка, валюта, язык), счётчики |
| `li_items` | товар: source_id, URL, handle, статус этапа, raw_json, нормализованные поля (title, description, price, currency, sku, brand, images[], variants[]), ru-поля, wc_product_id, хэш для дублей |
| `li_images` | картинка: item_id, исходный URL, локальный путь, attachment_id, статус |
| `li_translations` | кэш перевода: хэш исходного текста → перевод (одинаковые тексты не переводим дважды) |
| `li_log` | журнал: время, уровень, этап, item_id, сообщение |

### Статусы товара

`discovered → fetched → parsed → translated → priced → images_done → imported`, плюс `error`, `skipped` и `duplicate`.

## 4. Админка

Раздел **«Импорт каталога»** в меню WP. Доступ только у `manage_woocommerce`.

1. **Источники.** Поле для ссылки и кнопка «Добавить». Парсер сам определяет площадку и находит sitemap. В таблице источников: площадка, найдено / собрано / ошибок, кнопки «Сканировать», «Собрать», «Пауза», «Сброс».
2. **Прогресс.** Шкала по каждому этапу для каждого источника, скорость (товаров в минуту), оценка оставшегося времени. Обновляется опросом REST раз в 5 секунд.
3. **Товары (staging).** Таблица с фильтрами по источнику, статусу и бренду, поиск. Карточка показывает оригинал и перевод рядом, цену в EUR и RUB, фото. Есть ручная правка и действие «Переразобрать».
4. **Сопоставление категорий.** Коллекции и типы из источников сопоставляются с категориями нашего сайта. Это делается **до** импорта.
5. **Настройки.**
   - курс EUR→RUB, наценка (%), правило округления (например, до 10 ₽ или до 90 на конце);
   - кнопка «Пересчитать цены»: пересчёт по новому курсу без повторного парсинга;
   - ключ API перевода, глоссарий (бренды, коллекции и термины, которые не переводим);
   - задержка между запросами, число параллельных потоков, прокси (необязательно);
   - максимальное число фото на товар и размер, до которого их уменьшаем.
6. **Логи.** Последние ошибки с фильтром, экспорт в CSV.

## 5. Этапы работ

### Этап 0. Разведка (1–2 дня)

- [ ] На 20–30 товарах каждого сайта проверить, какие поля реально доступны: описание, цена, валюта, SKU/EAN, вариации, число фото.
- [ ] mdmaison: найти, откуда надёжнее брать данные (JSON-LD, встроенный JSON или HTML). Проверить, видна ли цена без авторизации и в какой валюте.
- [ ] Shopify: убедиться, что цена в `/products/<handle>.js` приходит в EUR (базовая локаль, без `/en-us`). Подобрать безопасную задержку, при которой не приходит 429.
- [ ] Посчитать среднее число фото на товар и объём текста в символах. Это нужно для оценки перевода и диска.
- [ ] Выбрать сервис перевода. Сравнить DeepL API и LLM (например, Claude) на выборке из 100 описаний: качество терминов (фарфор, хрусталь, столовое серебро), стоимость всего объёма, лимиты.
- [ ] Согласовать с клиентом: структуру категорий, нужны ли вариации, нужен ли бренд как отдельная таксономия, сколько фото брать на товар.

**Результат:** таблица полей по каждому сайту, выбранный переводчик, подтверждённая оценка объёма и бюджета.

### Этап 1. Каркас плагина (2–3 дня)

- [ ] Bootstrap плагина, создание таблиц при активации, удаление при деинсталляции.
- [ ] HTTP-клиент: лимит частоты на каждый домен, экспоненциальный backoff на 429/5xx, учёт `Retry-After`, таймауты, необязательный прокси.
- [ ] Очередь через Action Scheduler и команда `wp laress-import run --stage=<этап> --source=<id>`.
- [ ] Unit systemd или cron для воркера на VPS.
- [ ] Каркас админки: «Источники» и «Логи».

### Этап 2. Discovery и Fetch (2 дня)

- [ ] Разбор sitemap index → sitemap_products → URL товаров. Для Shopify берём только основную локаль, без `/en`, `/nl` и т. п.
- [ ] Загрузка сырых данных товара в `li_items.raw_json`.
- [ ] Прогон на одном небольшом источнике (daum.fr, 620 товаров).

### Этап 3. Адаптеры и Parse (3–4 дня)

- [ ] `ShopifyAdapter`: title, body_html, price (в центах, делим на 100), compare_at_price, vendor, product_type, tags, variants, images.
- [ ] `MdMaisonAdapter`: те же поля из разметки страницы.
- [ ] `GenericAdapter`: schema.org Product (JSON-LD) + OpenGraph как запасной вариант для новых сайтов.
- [ ] Очистка HTML описаний: убрать скрипты, стили и ссылки на сайт-источник, оставить разрешённые теги.
- [ ] Страница «Товары (staging)» с просмотром.

### Этап 4. Дубли (1 день)

- [ ] Сравнение по SKU/EAN, а если их нет, по нормализованным бренду, названию и размеру.
- [ ] Правило приоритета: официальный сайт бренда важнее mdmaison. Дубль помечается `duplicate` со ссылкой на основной товар.
- [ ] Ручная проверка спорных пар в админке.

### Этап 5. Перевод (2–3 дня разработки + время прогона)

- [ ] Провайдер перевода за интерфейсом, чтобы сервис можно было сменить без переделки.
- [ ] Перевод пакетами с сохранением HTML-разметки описания.
- [ ] Глоссарий: названия брендов и коллекций не переводим (Ginori 1735, Jaune de Chrome, Malmaison и т. д.), термины переводим единообразно.
- [ ] Кэш по хэшу текста: одинаковые описания внутри серии переводятся один раз.
- [ ] Выборочная вычитка ~50 товаров перед массовым прогоном.

### Этап 6. Цены (1 день)

- [ ] В meta храним исходную цену и валюту (`_li_price_orig`, `_li_currency`).
- [ ] Цена в рублях = исходная цена × курс × (1 + наценка), затем округление по правилу. Курс вводим вручную в настройках.
- [ ] Кнопка «Пересчитать цены» обновляет все импортированные товары пакетами.
- [ ] Товары без цены не публикуются: статус «черновик» или «Цена по запросу», по решению клиента.

### Этап 7. Изображения (2 дня разработки + время прогона)

- [ ] Скачивание оригиналов. У Shopify CDN можно сразу запросить нужную ширину (`?width=1600`).
- [ ] Конвертация в WebP (q≈85), загрузка в медиатеку, alt = русское название товара.
- [ ] **Перед импортом сократить набор размеров миниатюр WordPress** до реально используемых темой. Иначе каждое фото даст 6–10 файлов, и диск закончится.
- [ ] Ограничение числа фото на товар из настроек.
- [ ] Нормальные имена файлов: `brend-kollekciya-nazvanie-1.webp`.

### Этап 8. Импорт в WooCommerce (2–3 дня)

- [ ] Создание товаров через WooCommerce CRUD (`WC_Product_Simple` / `WC_Product_Variable`), а не через прямую запись в БД.
- [ ] Категории по таблице сопоставления. Бренд — таксономия `product_brand` (встроена в WooCommerce 9.6+) или атрибут.
- [ ] SKU, атрибуты (материал, размер, цвет), вариации.
- [ ] Связь `wc_product_id ↔ item_id`, чтобы повторный импорт обновлял товар, а не создавал копию.
- [ ] Во время массового импорта отключить пересчёт счётчиков терминов, отложить индексацию поиска и фильтров, затем выполнить их одним проходом.
- [ ] Первый прогон: 100 товаров со всех источников, проверка на витрине.

### Этап 9. Полный прогон и проверка (2–4 дня, в основном машинное время)

Порядок: daum.fr → degrenne → lalique → serax → jlcoquet → mdmaison. От маленьких к большим, чтобы ошибки всплыли на малом объёме.

- [ ] Сверка счётчиков: найдено = собрано + ошибки + дубли.
- [ ] Выборочная проверка 1% товаров с каждого источника: текст, цена, фото, категория.
- [ ] Повторный прогон товаров со статусом `error`.
- [ ] Отчёт для клиента: сколько импортировано, сколько пропущено и почему.

### Этап 10. Завершение (1 день)

- [ ] Пересобрать индексы фильтров и поиска, прогреть кэш.
- [ ] Бэкап БД и `uploads` после импорта.
- [ ] После приёмки отключить воркер. Плагин оставить: он пригодится для пересчёта цен и добавления новых источников.

**Итого:** ~20–25 рабочих дней разработки, плюс 2–4 суток машинного времени на полный прогон (сбор, перевод, картинки).

## 6. Сервер клиента (VPS)

| | Рекомендация |
|---|---|
| CPU | 6–8 vCPU (минимум 4) |
| RAM | 16 ГБ (минимум 8) |
| Диск | 250 ГБ NVMe |
| ПО | Nginx, PHP 8.3 + OPcache, MariaDB 10.11 / MySQL 8, Redis (object cache), WP-CLI, systemd |
| PHP | `memory_limit` 512M для CLI, расширения `imagick` или `gd` с поддержкой WebP, `curl`, `intl` |
| WooCommerce | включить HPOS, свой индекс для фильтров (FacetWP / FiboSearch и т. п.) |

## 7. Риски

| Риск | Что делаем |
|---|---|
| Блокировка IP сервера клиента (429 / бан) | медленная очередь с паузами, backoff; при необходимости прокси в настройках. Важно: блокируют **IP рабочего сайта**, поэтому лимиты держим консервативными |
| Изменение вёрстки mdmaison во время сбора | храним сырые данные, переразбор без повторной загрузки |
| Кривой перевод терминов | глоссарий + вычитка выборки до массового прогона |
| Нехватка диска из-за миниатюр | сократить размеры миниатюр до импорта, ограничить число фото |
| Импорт тормозит сайт | работа в фоне через CLI в ночное время, отложенная индексация; сайт до запуска закрыт от посетителей |
| Разные цены по регионам | берём одну базовую локаль на источник, валюту сохраняем вместе с ценой |

## 8. Открытые вопросы к клиенту

1. Структура категорий сайта: своя или берём из источников?
2. Вариации (размер, цвет) оставить отдельными вариациями или делать каждую отдельным товаром?
3. Сколько фото максимум на товар?
4. Наценка и правило округления цены.
5. Что делать с товарами без цены или со статусом «нет в наличии» у источника?
6. Сервис перевода и бюджет на него (после этапа 0).
7. Доступ к VPS: SSH, версии PHP/MySQL, есть ли уже WooCommerce.
